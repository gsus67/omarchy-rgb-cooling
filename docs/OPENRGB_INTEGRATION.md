# OpenRGB 1.1 integration notes

## Scope and evidence labels

This is a read-only source investigation of Arch `extra/openrgb 1.1-1`, whose PKGBUILD builds upstream tag `release_1.1`. The tag resolves to commit [`8e16de27858cf2be6af54a33ce003df74cb9fd3e`](https://gitlab.com/CalcProgrammer1/OpenRGB/-/commit/8e16de27858cf2be6af54a33ce003df74cb9fd3e). `[V]` means directly verified in this source or package file; `[I]` is an inference from that code; `[NV]` means not verified by the examined source. File links use the upstream tag and line anchors where available.

Arch package source: [PKGBUILD](https://gitlab.archlinux.org/archlinux/packaging/packages/openrgb/-/blob/main/PKGBUILD), [upstream release tag](https://gitlab.com/CalcProgrammer1/OpenRGB/-/tree/release_1.1).

## 1. CLI, server and headless operation

- [V] The relevant options are `--server`; `--server-host <host>` (default `127.0.0.1`); `--server-port <port>` (default `6742`, accepted range 1024–65535); `--noautoconnect`; `--config <path>`; `--localconfig`; `--nodetect`; and `--loglevel <0-6|error|warning|...>`. Log levels are fatal 0 through trace 6. See [`cli.cpp` lines 420–452](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/cli.cpp#L420-452), parsing at [1205–1234](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/cli.cpp#L1205-1234).
- [V] Binding only to loopback is supported: use `--server-host 127.0.0.1`; loopback is also the default. The SDK header defines `OPENRGB_SDK_HOST` as `127.0.0.1` and port 6742 ([`NetworkProtocol.h` lines 24–38](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkProtocol.h#L24-38)).
- [V] CLI operation without `--gui` is supported. The help says GUI appears when no parameters are passed, and `--gui` explicitly requests it; server mode is an option in the same CLI ([`cli.cpp` lines 417–425](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/cli.cpp#L417-425)). The README explicitly says it can run as a “client/headless server” ([README line 14](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/README.md#L14)). `--startminimized` means GUI plus tray, so omit it for headless use.
- [I] The server can run without an X/Wayland display when invoked as a non-GUI CLI command, but the source/docs inspected here do not explicitly state a display-server requirement for each build configuration. The Arch package links Qt6; no GUI is requested by `--server` itself.

Suggested invocation: `openrgb --server --server-host 127.0.0.1 --server-port 6742 --noautoconnect --config "$XDG_RUNTIME_DIR/openrgb-plugin" --loglevel warning`.

## 2. Detectors and configuration

### MSI Mystic Light `1462:7d98`

- [V] A HID detector exists with exact registered name **`MSI Mystic Light MS_7D98`**, matching VID `0x1462`, PID `0x7D98`, usage page `0x0001`, usage `0x00`. See [`MSIMotherboardControllerDetect.cpp` line 221](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/Controllers/MSIMotherboardController/MSIMotherboardControllerDetect.cpp#L221).
- [V] For PID 7D98 the 185-byte controller table assigns `DIRECT_MODE_PER_LED`; its exposed modes include **Direct** when direct mode is supported, and **Static** (brightness + per-LED color, manual-save flag), along with effects. See [`MSIMotherboard185Controller.cpp` lines 341–352](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/Controllers/MSIMotherboardController/MSIMotherboard185Controller/RGBController_MSIMotherboard185.cpp#L341-352). Static is the better minimal choice for a single flat color; Direct uses per-LED colors.
- [V] The detector has a source warning that Mystic Light had a historical bricking risk; code claims it was fixed on tested boards and untested boards remain disabled behind `ENABLE_UNTESTED_MYSTIC_LIGHT` ([detector lines 22–28](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/Controllers/MSIMotherboardController/MSIMotherboardControllerDetect.cpp#L22-28)). This does not establish that every 7D98 board/firmware is safe.
- [NV] Issue 4012 and MR 3453 are not referenced in the 1.1 source tree examined here, so their current applicability or resolution cannot be asserted from this code.

### Other queried IDs

- [V] No registration or string match for Corsair **VANGUARD 96 `1b1c:2b0d`** was found in the release_1.1 controller registrations. The searched source contains many Corsair detector registrations but no PID 2B0D. This is a source-tree negative, not proof that no generic path can expose it.
- [V] No HID registration for `0416:5302` was found. The value `0x5302` occurs in the source as an **MSI NVIDIA GPU PCI subsystem-device ID**, not a Winbond/Thermalright USB ID ([`pci_ids.h` line 884](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/pci_ids/pci_ids.h#L884); [MSI GPU detector](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/Controllers/MSIGPUController/MSIGPUv2Controller/MSIGPUv2ControllerDetect.cpp#L78)). No matching `0416:5302` HID detector was found.

### Disabling detectors and dedicated config

- [V] Detector settings are under settings key `Detectors`, with a nested object named lowercase `detectors`; the detector table reads `settings["detectors"]` and writes booleans by exact registered detector key ([`DetectorTableModel.cpp` lines 20–31 and 138–155](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/qt/DetectorTableModel.cpp#L20-31)). The settings schema registers `Detectors` ([`ResourceManager.cpp` lines 243–246](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/ResourceManager.cpp#L243-246)).
- [V] The intended JSON shape is therefore `"Detectors": { "detectors": { "MSI Mystic Light MS_7D98": false } }`. OpenRGB's main config file is `OpenRGB.json`; validate the nesting/merging behavior against the exact generated file for the installed build before relying on hand-edited settings. [I] The source indicates false disables the named detector in settings, but the detector execution filtering path should be reviewed if doing broad disablement.
- [V] `--config <path>` selects a custom config directory and `--localconfig` selects the current working directory ([CLI help above; parsing lines 1450–1475](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/cli.cpp#L1450-1475)). A per-plugin directory is supported; keep its `OpenRGB.json` independent from the user's normal GUI configuration.

## 3. Permissions and hardware access

- [V] Arch `PKGBUILD` runs `./openrgb --generate-udev-rules "$pkgdir"/usr/lib/udev/rules.d/60-openrgb.rules` during packaging; package `1.1-1` therefore installs the generated `60-openrgb.rules` ([PKGBUILD](https://gitlab.archlinux.org/archlinux/packaging/packages/openrgb/-/blob/main/PKGBUILD)). The generator emits `TAG+="uaccess"` for I2C bus nodes and serial ports, not a global `MODE=0666` rule ([`DetectionManager.cpp` lines 2321–2332](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/DetectionManager.cpp#L2321-2332)); generated HID rules likewise use uaccess tags, device by device (see [lines 2334 onward](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/DetectionManager.cpp#L2334)).
- [I] A normal logged-in desktop user with active udev-logind `uaccess` ACLs should be able to open the MSI USB HID device without root if its generated per-device rule matches. This is a runtime ACL/environment condition, not guaranteed solely by installing the package. Check the actual `/dev/hidraw*` ACL if access fails.
- [V] Arch lists `i2c-tools` as an optional dependency for motherboard and RAM access; it is not required for HID-only paths (PKGBUILD `optdepends`). [I] RAM RGB and motherboard SMBus drivers commonly need `/dev/i2c-*` access and sometimes kernel/module setup. Avoid RAM/SMBus scans and I2C Tools for this integration; they expand scope and the source warns invalid I2C/SMBus transactions can brick hardware ([CLI lines 445–447](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/cli.cpp#L445-447)).

## 4. SDK protocol details (protocol version 6)

- [V] SDK packets use header `{char magic[4]="ORGB"; uint32 device_id; uint32 packet_id; uint32 payload_size}`; packet IDs and protocol version are in [`NetworkProtocol.h` lines 24–50, 187–202](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkProtocol.h#L24-50). Default port 6742, default host loopback, protocol version 6 ([lines 13–38](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkProtocol.h#L13-38)). Fields are native C++ integer encodings; use a matching SDK implementation rather than assume network byte order.
- [V] IDs: `UPDATELEDS=1050`, `UPDATEZONELEDS=1051`, `SETCUSTOMMODE=1100`, `UPDATEMODE=1101`, `SAVEMODE=1102` ([`NetworkProtocol.h` lines 193–199](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkProtocol.h#L193-199)). Each request's packet header `device_id` selects the controller. `SETCUSTOMMODE` has empty payload and calls `SetCustomMode()` ([`NetworkServer.cpp` lines 2951–2975](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkServer.cpp#L2951-2975)).
- [V] `UPDATEMODE`/`SAVEMODE` payload starts with `uint32 payload_size`, `int32 mode_index`, then a serialized mode description. For protocol 6, description is: `uint16 name_len`, name bytes; `uint32 flags`; `uint32 speed_min,max`; `uint32 brightness_min,max`; `uint32 colors_min,max`; `uint32 speed,brightness,direction,color_mode`; `uint16 color_count`; then `uint32 RGBColor` per color. Protocol 6 omits the older `mode.value` field. Parser: [`RGBController.cpp` lines 3704–3794](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/RGBController/RGBController.cpp#L3704-3794); request handler calls UpdateMode or SaveMode ([`NetworkServer.cpp` lines 3163–3265](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkServer.cpp#L3163-3265)).
- [V] Mode flags: speed bit 0, directions bits 1–3 and 11, brightness bit 4, per-LED color bit 5, mode-specific color bit 6, random color bit 7, manual-save bit 8, automatic-save bit 9, whole-device bit 10. `MODE_COLORS_NONE=0`, `PER_LED=1`, `MODE_SPECIFIC=2`, `RANDOM=3` ([`RGBControllerInterface.h` lines 62–104](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/RGBController/RGBControllerInterface.h#L62-104)).
- [V] Minimal static color: discover the controller and mode descriptor first; choose the actual `Static` mode index; send `UPDATEMODE` with that mode's exact name/limits/flags, brightness in its supported range, `color_mode=MODE_COLORS_PER_LED`, and the appropriate color count plus packed RGB values. For this source's packed `RGBColor`, `ToRGBColor(r,g,b)` stores R in the low byte, G next, B high ([`RGBControllerInterface.h` lines 23–29](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/RGBController/RGBControllerInterface.h#L23-29)). For the MSI static mode, flags advertise brightness and per-LED color ([controller lines 346–352](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/Controllers/MSIMotherboardController/MSIMotherboard185Controller/RGBController_MSIMotherboard185.cpp#L346-352)). Call `UPDATEMODE`; avoid `UPDATELEDS` unless using Direct/custom colors. `UPDATELEDS` payload: `uint32 size`, then `uint16 num_colors`, then `uint32 RGBColor[num_colors]`; it updates controller color buffer and calls UpdateLEDs ([`NetworkServer.cpp` lines 3094–3158](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkServer.cpp#L3094-3158), [`RGBController.cpp` lines 3617–3665](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/RGBController/RGBController.cpp#L3617-3665)). `UPDATEZONELEDS` is `uint32 size`, `uint32 zone_index`, `uint16 color_count`, then `uint32 RGBColor[]`; server bounds-checks the zone and count ([`NetworkServer.cpp` lines 3350–3447](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_1.1/NetworkServer.cpp#L3350-3447)).
- [I] `UPDATEMODE` changes hardware state but persistence after OpenRGB exits or machine restart is device/firmware-specific. Static is marked `MODE_FLAG_MANUAL_SAVE`, which signals that a separate save operation may be needed; no universal persistence guarantee follows from the SDK.
- [V] `SAVEMODE` exists (ID 1102) and invokes the controller's `SaveMode()` after parsing and applying the mode descriptor ([handler above]). [I] It can write device-side persistent state and should be treated as a potentially persistent hardware action; only use it when the device's save semantics are understood. It is not needed for ordinary temporary color updates.

## 5. Recommendation for an unprivileged on-demand plugin

- Run OpenRGB as a **user-owned systemd unit** only when the plugin needs it, with `ExecStart=/usr/bin/openrgb --server --server-host 127.0.0.1 --server-port 6742 --noautoconnect --config %h/.config/openrgb-plugin --nodetect` only if the plugin intentionally manages controller discovery itself. Otherwise omit `--nodetect` and store a minimal detector allowlist in the dedicated config. `--nodetect` avoids startup discovery altogether, so it is incompatible with discovering the HID controller on each cold start unless device list state is otherwise available.
- Limit that config to the intended MSI detector and disable unrelated entries only after confirming the JSON key names from an OpenRGB-generated settings file. Use the SDK client on `127.0.0.1:6742`, select the controller and `Static` mode from runtime descriptors, then issue `UPDATEMODE`. No root service or broad I2C permissions are needed for the USB HID path if udev grants this user access.
- Start with `systemctl --user start openrgb-plugin.service`; stop with `systemctl --user stop openrgb-plugin.service`. On-demand activation can use a user socket unit, or the plugin can start/stop the service around SDK requests. Do not enable the system-wide package service: its packaged unit is a system service and runs with root permissions ([package service source](https://gitlab.archlinux.org/archlinux/packaging/packages/openrgb/-/blob/main/openrgb.service)).
- Risks: another OpenRGB instance may hold the HID interface; startup detection may probe devices beyond the target; loopback limits remote access but any local process can connect to the SDK and issue hardware commands; firmware persistence is device-specific; `SAVEMODE` and SMBus/I2C operations have broader hardware consequences. Use the exact detected controller/mode at runtime rather than hard-coded array indices.

## Resumen

OpenRGB 1.1 ofrece servidor SDK headless en `127.0.0.1:6742`. Detecta la placa MSI `1462:7d98` como `MSI Mystic Light MS_7D98`, con modos `Direct` y `Static`; conviene usar `Static` y dejar `SAVEMODE` fuera del flujo normal. Arch instala reglas udev con `uaccess`, no permisos globales 0666: HID puede funcionar sin root con ACL activa, mientras que RAM/SMBus debe quedar fuera del plugin. Una unidad systemd de usuario con configuración dedicada y detección mínima reduce el alcance.
